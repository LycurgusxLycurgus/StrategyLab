# Pre-systematic-v2 document archive

`manifest.json` records 24 intended snapshots from before the systematic phase and operator replacement dated 2026-10-23. `source_path` is relative to the repository root; `archive_path` is the archived file's full repository-relative path; `sha256` and `bytes` are the recorded expected bytes. The initial source-to-archive comparison matched all 24 records, but a later path collision replaced the archived root `README.md` with a guide: that archive path currently contains 1,301 bytes rather than the recorded 11,180 bytes (SHA-256 `821056aebec01b052b5bc76fa337f2a747df58b172d0c01bf9d4ac189939fad4`). The other 23 snapshots remain verified. `README.recovered.md` is an unverified text reconstruction, not a byte-verified backup; it does not satisfy the README manifest record.

The archived operator and ten former phase prompts retain their original repository-relative directory structure beneath this archive. This is a historical recovery copy, not an active prompt set. The application discovers prompts only from direct `*.md` files in the configured prompt directory; nested archive documents are not auto-discovered. Existing runtime paths, APIs, and workflow identifiers are not renamed by this documentation archive.

Restore only after explicit user authorization. Restoring a snapshot over an active path would replace the current document and must not happen automatically. Use the manifest to select the intended file, verify its SHA-256, and copy it deliberately to the matching `source_path`; never bulk-restore the archive as part of normal startup or prompt discovery. The original README byte snapshot remains an unresolved recovery gap; do not treat the unverified reconstruction as restorable evidence.
