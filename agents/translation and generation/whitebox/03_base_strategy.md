# Phase 3 — Base strategy

Consolidate the qualifying Phase 2 candidate as a reproducible Python base with a fixed accepted economic baseline, preserving its tested rules and context.

## Operating contract

Read `AGENTS.md`, `agents/translation and generation/agents/codex_phase_operator.md`, relevant architecture and unresolved-proof entries before acting. Schedule: `systematic_v2`; runtime workflow selectors remain unchanged. Work within authorized scope/budget, preserve immutable evidence, and report missing prerequisites honestly. The operator's shared report/evidence contract applies. Use neutral requirements, not illustrative strategies, assets, parameter values or trading rules.

## Inputs

Require a Phase 2 candidate that met every predeclared advancement requirement, its exact accepted causal rules/code/settings, qualifying asset/timeframe/direction scope, complete comparison and gate evidence, source/translation provenance, unresolved limitations, cumulative trial ledger, protected holdouts, remaining budget, campaign contract and original data. A relative winner without qualifying evidence is not an accepted input. Require the approved minimum-three candidate batch's comparison record and separate measurement/signal/economic verdicts. A retained promising or supported component from a failed strategy is research evidence only, not a Phase 3 entrant. Read the production backtest engine contract; engine support must be demonstrated, not assumed.

## Task

1. Consolidate the already tested executable strategy specification: indicator states, information availability, confirmation/invalidation/expiry, entry/exit/risk/sizing rules and supported order behavior. Preserve requested-method classification, historical origin/operation, translation category and per-rule transformation provenance. Do not introduce untested behavioral decisions or combinations; substantive changes or expanded contexts require updated specifications and a return to Phase 2 comparison before base acceptance.
2. If a novel indicator is required, implement and accept it first, then add a strategy child. Build independent hand-worked/constructed positive, negative and boundary cases covering every applicable causal, state and execution invariant. Map each rule to code and cases.
3. Implement or extend the minimum adequate Python engine. Audit raw and normalized data, timestamps, duplicates/gaps, revisions, missing values and every repair. Verify causal state/signal/order/fill/position traces against independent expectations and visual context.
4. Verify realistic order submission/fills, venue sizing, costs, funding/borrow where relevant, open-position mark-to-market accounting and failure behavior. Unsupported behavior blocks acceptance; favorable fill ordering must not be invented.
5. Run the fixed unoptimized base under its qualifying frozen development contexts. Save code/settings/data hashes, independent semantic proof, data audit, execution proof, visual ledger, economic report and immutable parent. Source fidelity and reference correctness remain distinct.
6. Define explicit finite search domains/objective/budget and obtain existing runtime baseline-backed authorization before Phase 4. Respect current API authorization schema; reserve its required holdout as well as the campaign's final holdout. Search never authorizes inspection of either reserved window.

## Output and validation

Deliver one accepted base package and shared phase report with the qualifying contexts, inherited comparison gates, complete trial accounting and protected evaluation windows. PASS_TO_PHASE_4 requires semantic/data/execution acceptance, reproducible fixed baseline and valid search authorization, plus the campaign's declared economic potential criteria. Repair correctness defects here; RETURN_TO_PHASE_2/1 for a weak hypothesis. BLOCKED if required engine/data/evidence is unavailable. Pine is optional and is not an early prerequisite.

Include exact artifacts, reproducible commands, source/code/settings/data identities, separate correctness/fidelity/execution/economic/target verdicts, controls, uncertainties, budget and next action. A later phase never compensates for failed earlier proof.
