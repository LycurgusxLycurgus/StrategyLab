# Phase 5 — Mutation + optimization

Produce one frozen finalist through a single bounded structural-mutation and reoptimization loop, then evaluate it once on untouched final evidence.

## Operating contract

Read `AGENTS.md`, `agents/translation and generation/agents/codex_phase_operator.md`, relevant architecture and unresolved-proof entries before acting. Schedule: `systematic_v2`; runtime workflow selectors remain unchanged. Work within authorized scope/budget, preserve immutable evidence, and report missing prerequisites honestly. The operator's shared report/evidence contract applies. Use neutral requirements, not illustrative strategies, assets, parameter values or trading rules.

## Inputs

Require accepted Phase 4 candidate, immutable parent/proofs, qualifying context scope and prior comparison decisions, cumulative ledger including all candidate/context trials, remaining budgets and reserved final window. Read the universal mutation constitution. Diagnostics, mutation, hybrid rule combinations and successor decisions are techniques inside this phase.

## Task

1. Diagnose concrete failure mechanisms on development data. Propose admissible structural changes to entries, exits, risk allocation, context filters or rule combinations. Define causal rationale, falsification/ablation and complexity costs before trials. Keep the accepted context scope; extending it requires preregistered qualification, not extrapolation from previous winners.
2. Freeze finite mutation families, round/stopping budgets and inherited invariants. “All possible mutations” means all admissible families assessed for this campaign, not infinite enumeration. Each child has an immutable parent, exact delta and effective settings.
3. Revalidate impacted semantics/data/execution before economic comparison. Save a fixed unoptimized child baseline and obtain valid child search authorization before bounded reoptimization. Preserve runtime parent-domain/authorization rules; do not stretch an old grant to cover new semantics.
4. Compare parent, child, relevant ablations and simple controls under common context and comparable development budgets. Integrate only supported changes; repeated failures stop a branch. Track every proposal, manual decision and run.
5. Learned policy, decision-model, RL and social-data branches remain deferred under the future roadmap unless separately authorized and supported by point-in-time data, a causal engine/adapter and independent validation. Do not silently introduce them as a mandatory phase.
6. Select and freeze exactly one finalist, code/settings/data/execution identities, acceptance criteria and target. Perform the final holdout evaluation once. Save failure as well as success; an inspected window is consumed and cannot guide retuning while still called untouched.
7. If Pine is a required target, compile and corroborate the exact final candidate in TradingView before paper trading using the operator's Basic-compatible scoped comparison. Do not claim whole-performance parity from sampled screenshots or different feeds.

## Output and validation

Deliver a frozen finalist with qualifying context scope, inherited comparison decisions, mutation/optimization lineage, controls, complete trial accounting and final-test verdict. PASS_TO_PHASE_6 requires predeclared final acceptance plus all current correctness/execution and required target evidence. Failed final acceptance means STOP/NOT_QUALIFIED; revisiting research requires a new campaign and fresh/forward evaluation evidence. BLOCKED for missing proof/capability; never erase consumed holdouts or substitute in-sample success.

Include exact artifacts, reproducible commands, source/code/settings/data identities, separate correctness/fidelity/execution/economic/target verdicts, controls, uncertainties, budget and next action. A later phase never compensates for failed earlier proof.
