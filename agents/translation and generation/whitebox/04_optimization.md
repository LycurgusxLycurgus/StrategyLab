# Phase 4 — Optimization

Produce a context-specific, stable parameterized candidate without changing accepted rule meaning.

## Operating contract

Read `AGENTS.md`, `agents/translation and generation/agents/codex_phase_operator.md`, relevant architecture and unresolved-proof entries before acting. Schedule: `systematic_v2`; runtime workflow selectors remain unchanged. Work within authorized scope/budget, preserve immutable evidence, and report missing prerequisites honestly. The operator's shared report/evidence contract applies. Use neutral requirements, not illustrative strategies, assets, parameter values or trading rules.

## Inputs

Require the accepted Phase 3 immutable base, all current proof, finite baseline-backed search authorization, objective, chronology and budgets. Inherit the qualifying asset/timeframe/direction scope, comparison evidence, trial ledger and protected windows from Phases 2–3. Optimize only within that accepted scope; a new context requires its own preregistered comparison and qualification.

## Task

1. Inventory all legitimate tunable strategy parameters with units, constraints, finite candidate values and rationale. All parameters may be considered; exhaustive Cartesian enumeration is not required. Keep implementation constants, risk ceilings and execution legality fixed.
2. Run the accepted unoptimized parent before search. Keep every evaluated child inside authorized domains; record effective parameters and parent identity. If an existing authorization field is called holdout, leave it untouched during search; choose development folds within authorized training.
3. Select on development data only using predeclared objective and costs. Check chronological stability, neighboring parameter behavior, trade concentration and uncertainty under comparable risk. Account for the complete cumulative trial count, including failed/manual trials.
4. Re-earn affected semantic/data/execution evidence for parameter-dependent behavior. Repair defects instead of optimizing around them. Never spend the campaign's final holdout to choose a setting.
5. Save a small justified candidate set or one candidate according to the frozen selection policy. Record all trials, budget and limits; avoid presenting an isolated in-sample maximum as expected future return.

## Output and validation

Deliver the selected parameterization, qualified contexts, parent-relative results, stability evidence, inherited comparison decisions and complete cumulative search ledger. PASS_TO_PHASE_5 requires authorized reproducible search and context-specific acceptance. A rule change belongs to Phase 5, correctness defects RETURN_TO_PHASE_3, and an unpromising concept returns to Phase 2/1 or STOP. Missing authorization/evidence means BLOCKED. Do not retune using a reserved evaluation window.

Include exact artifacts, reproducible commands, source/code/settings/data identities, separate correctness/fidelity/execution/economic/target verdicts, controls, uncertainties, budget and next action. A later phase never compensates for failed earlier proof.
